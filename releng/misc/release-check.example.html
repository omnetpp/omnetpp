Findings

1. opp_test rejected its documented -a … -- files form on Python 3.15

fixed · 02271e2c10 · verified

python/omnetpp/test.py declared -a/--args with nargs=argparse.REMAINDER. In Python 3.15 that option also takes the -- and the test files after it, so any opp_test … -a ARGS -- *.test call failed. test/core/runtest uses that form, so test_core could not run on macOS, where Homebrew's python3 is now 3.15. The error path also crashed, because OppFormatter called a private argparse method that 3.15 removed.

The fix takes -a/--args and everything up to -- out of sys.argv before argparse runs, and removes OppFormatter. In this build, test_core passes with the stock runtest on macOS and on Fedora 46, both with Python 3.15.2.

2. The Windows toolchain's MSYS2 runtime crashes on every fork under Wine

open · Wine only

The Windows archive still ships toolchain msys2-runtime 3.6.1-4. Under Wine 11.15, the first command that forks, such as $(...), ends the shell: in this build, bash -c "echo a; x=$(echo b); echo $x" printed a and nothing after it. As a result, the shell from mingwenv.cmd does nothing, and configure and make cannot run. Replacing usr/bin/msys-2.0.dll with the one from msys2-runtime 3.6.10 fixes it, and every Windows result above was produced that way. The windows-box README already notes that 3.6.1 fails and 3.5.7 and 3.6.11 work.

Native Windows is probably not affected. The toolchain is from June 2025 (clang 20.1.5, Qt 6.9.0, Python 3.12.10). If Wine and windows-box testing should work with the release archive, rebuild the toolchain with msys2-runtime 3.6.10 or newer.

3. Four histogram fingerprints failed on Windows under Wine

fixed · qsuxrwrm, not in this build
/samples/histograms/      -c Normal              wine f76e-b688/rsz

/test/models/histograms/  -c UnitNormal          wine e99a-f1aa/rsz
/test/models/histograms/  -c SineWeightedLinear  wine 375a-ca1d/rsz

These are the same values as in the previous build. All four tests use transcendental math, and Wine's ucrtbase math functions give slightly different results from Microsoft's. The Wine values are now listed as a fourth accepted fingerprint. tests.csv and samples.csv each have one comment line at the top: platform dependent tests list their fingerprints in "linux macos windows wine" order, because transcendental functions are implemented differently on each platform.

The Linux, macOS and Wine values were measured from this build, and they match the order note. The native Windows values are the ones added in b34d1e3601. For SineWeightedUniform, Wine gives the same value as native Windows (tests.csv) and as Linux (samples.csv), so those rows needed no new value. Rerun with the new CSVs: 142/142 under Wine and on Ubuntu 26.04. On macOS only values were added, so it was not rerun.

4. install.sh installed libdwarf instead of libdw on Fedora and Arch

fixed · 804d6382aa · verified

Configure checks only for libdw, which comes from elfutils. install.sh now installs elfutils-devel on Fedora and elfutils on Arch, and the install guide chapters were corrected to match. In this build, configure finds libdw on all 9 distros, including Fedora 44, where it was missing before.

5. The RHEL chapter said install.sh asks about 3D; it exited instead

fixed · xxpsnmvq, not in this build

ch-redhat.rst said install.sh "will prompt you" to disable OpenSceneGraph. In this build, without --no-3d, the script prints "Please disable the 3D support with --no-3d" and exits with code 1 before installing anything, on both AlmaLinux 9 and 10.

Fix (xxpsnmvq): on RHEL, AlmaLinux and Rocky, install.sh now asks whether to continue without 3D support. With -y it continues; answering no exits with a hint about --no-3d. The RHEL chapter now describes this. Checked on AlmaLinux 9 and 10 with the fixed script: -y configures with WITH_OSG=no and builds, and fifo runs; answering no exits with code 1. The fix needs a new build to reach the archives.
